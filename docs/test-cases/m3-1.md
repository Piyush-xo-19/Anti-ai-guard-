# M3.1 Windows event source access

The first run checks whether a Windows 11 standard-user account can open the
two candidate sources. It uses the desktop .NET Framework compiler and
System.Management for the WMI probe, plus the native ETW controller API.
Run it from an ordinary Windows PowerShell terminal in the repository:

```powershell
.\scripts\labs\run-m3-process-events.ps1 -Consent
```

The runner compiles the x64 probe into a fresh ignored `target` directory.
It supplies the environment opt-in and mode flag to each owned worker and
allows up to 12 seconds per worker. The probe refuses accounts with enabled
administrator or Performance Log Users roles and the built-in service identities.

| Case | Procedure and expected evidence |
| --- | --- |
| M3.1-CONSENT | Run without each opt-in. Expect exit 2 before any namespace or trace call. |
| M3.1-WMI-START | Connect to local `root\cimv2` and request `Win32_ProcessStartTrace`. Record namespace access separately from subscription access. |
| M3.1-WMI-STOP | Repeat independently with `Win32_ProcessStopTrace`. |
| M3.1-ETW-CONTROL | Attempt `StartTraceW` with zero enabled providers and no trace file. If it starts, stop only the session identified by the returned handle. |

The WMI query projects process ID, parent ID, session ID and event timestamp.
It filters by the current session, this worker as parent and its generated
executable name. The lab launches no matching child. Receipt attempts use a
400 ms timeout with one event requested at a time. The probe discards any
unexpected event without printing its fields. An authorized subscription
would still need separate delivery, scope and loss tests. [WMI notification API](https://learn.microsoft.com/en-us/windows/win32/api/wbemcli/nf-wbemcli-iwbemservices-execnotificationquery)

ETW control uses a single descriptive session name. A name collision is an
error, and the probe stops only a handle from its own successful start.
A successful control check would warrant a separate provider experiment.
[ETW controller access](https://learn.microsoft.com/en-us/windows/win32/etw/controlling-event-tracing-sessions)

Probe exit 3 records a permission denial. The runner treats that as a valid
experimental outcome. Source readiness, event receipt and continuity stay
unverified if access is denied.
