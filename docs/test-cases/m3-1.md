# M3.1 Windows event source access

The first run checks whether a Windows 11 standard-user account can open the
two candidate sources. It uses the desktop .NET Framework compiler and
System.Management for the WMI probe, plus the native ETW controller API.
Run it from an ordinary Windows PowerShell terminal in the repository:

```powershell
.\scripts\labs\run-m3-process-events.ps1 -Consent
```

The runner compiles the x64 probe into a fresh ignored `target` directory.
It supplies the environment opt-in and mode flag to each owned worker and
allows up to 12 seconds per worker. The probe refuses accounts with enabled
administrator or Performance Log Users roles and the built-in service identities.

| Case | Procedure and expected evidence |
| --- | --- |
| M3.1-CONSENT | Run without each opt-in. Expect exit 2 before any namespace or trace call. |
| M3.1-WMI-START | Connect to local `root\cimv2` and request `Win32_ProcessStartTrace`. Record namespace access separately from subscription access. |
| M3.1-WMI-STOP | Repeat independently with `Win32_ProcessStopTrace`. |
| M3.1-ETW-CONTROL | Attempt `StartTraceW` with zero enabled providers and no trace file. If it starts, stop only the session identified by the returned handle. |

The WMI query projects process ID, parent ID, session ID and event timestamp.
It filters by the current session, this worker as parent and its generated
executable name. The lab launches no matching child. Receipt attempts use a
400 ms timeout with one event requested at a time. The probe discards any
unexpected event without printing its fields. An authorized subscription
would still need separate delivery, scope and loss tests. [WMI notification API](https://learn.microsoft.com/en-us/windows/win32/api/wbemcli/nf-wbemcli-iwbemservices-execnotificationquery)

ETW control uses a single descriptive session name. A name collision is an
error, and the probe stops only a handle from its own successful start.
A successful control check would warrant a separate provider experiment.
[ETW controller access](https://learn.microsoft.com/en-us/windows/win32/etw/controlling-event-tracing-sessions)

Probe exit 3 records a permission denial. The runner treats that as a valid
experimental outcome. Source readiness, event receipt and continuity stay
unverified if access is denied.

## Elevated ETW delivery in a disposable Windows 11 guest

This comparison requests process start/stop from the
`Microsoft-Windows-Kernel-Process` provider, using process keyword `0x10` and event
IDs 1 and 2. The real-time session can receive machine-wide process events in
the guest. Use an isolated x64 Windows 11 guest with only synthetic activity and
an explicitly elevated PowerShell terminal. Keep machine-wide collection off
the daily-use host.

Build from a clean checkout using [Zig 0.15.2](https://ziglang.org/download/).
No Zig install is needed in the guest. Record the source revision and copy only
the resulting executable into the guest.

```powershell
New-Item -ItemType Directory -Force target | Out-Null
zig cc -target x86_64-windows-gnu -std=c11 -Wall -Wextra -Werror -municode `
  scripts/labs/m3-etw-delivery.c -o target/m3-etw-delivery.exe -ladvapi32 -ltdh
```

In the elevated guest terminal, record the Windows release and full build. Set
the opt-in only for this run.

```powershell
$env:GUARD_M3_ETW_DELIVERY_LAB = 'yes'
try {
    .\m3-etw-delivery.exe --consent
    $trialExit = $LASTEXITCODE
} finally {
    Remove-Item Env:GUARD_M3_ETW_DELIVERY_LAB
}
$trialExit
```

| Case | Expected evidence |
| --- | --- |
| M3.1-ETW-DELIVERY-CONSENT | Missing environment opt-in or flag returns 2 before token inspection or trace creation. |
| M3.1-ETW-DELIVERY-TOKEN | Valid opt-ins on a non-elevated token return 3 before trace creation. |
| M3.1-ETW-DELIVERY-FIXTURES | The held child and two fast exits each produce one matched start and one matched stop. Association uses PID and creation FILETIME. Start additionally checks parent and session. |
| M3.1-ETW-DELIVERY-CLEANUP | Stop the owned session, close the consumer, wait for its worker and release child handles. Record ETW loss counters and typed cleanup status. |

The lab accepts up to 1,024 provider events within an eight-second receive window,
followed by cleanup. It reads numeric process identifiers to recognize owned
fixtures and discards unrelated records. Output contains aggregate counts,
schema versions and status codes. The lab creates no ETL file. Positive results
cover the three owned launches in the recorded guest and token configuration.
Reported loss counters cover loss visible to that session.

A name collision ends the run without stopping the existing session. Use Ctrl+C
for cooperative cancellation. If the executable or guest is interrupted before
cleanup completes, shut down the disposable guest before retrying. Exit 0 means
the owned fixture and cleanup criteria passed. Exit 1 means incomplete or failed
setup, receipt or cleanup. Exit 3 also covers session creation denied by Windows.
